# 업체 관리 페이지 기획서

**문서 버전** 0.1
**작성일** 2026-08-03
**대상 시스템** 답해줘 운영 콘솔 (내부용 백오피스)
**범위** 운영 콘솔 내 `업체` 메뉴

---

## 1. 개요

### 1.1 목적

챗봇 SaaS를 이용하는 업체(테넌트)의 계정 상태, 사용량, 수익성을 한 곳에서 파악하고, CS·영업 대응에 필요한 조치를 즉시 실행하기 위한 내부 화면이다.

### 1.2 해결하려는 문제

| 문제 | 현재 상태 | 이 화면이 하는 일 |
|---|---|---|
| 문의가 들어와도 그 업체 상황을 모른다 | DB를 직접 조회 | 업체 상세에서 즉시 확인 |
| 어떤 업체가 적자인지 모른다 | 집계 안 됨 | 원가율을 목록에 상시 노출 |
| 재현이 안 되는 버그 문의 | 대응 불가 | 대리 로그인으로 동일 화면 확인 |
| 이탈 조짐을 놓친다 | 해지 통보를 받고서야 인지 | 미접속·사용량 급감 필터 |

### 1.3 사용자

| 역할 | 인원 | 필요한 권한 |
|---|---|---|
| 운영 관리자 | 1~2명 | 전체 |
| CS 담당 | 1~3명 | 조회 + 대리 로그인 + 쿼터 증량 |
| 영업 담당 | 1~2명 | 조회 + 메모 + 체험 연장 |

초기에는 전원이 전체 권한을 갖되, 역할 구분은 데이터 모델에 미리 반영해 둔다.

### 1.4 범위

**포함** — 업체 목록, 업체 상세, 상태 변경, 대리 로그인, 쿼터·체험 조정, 내부 메모

**제외** — 수익성 분석(별도 화면), AI 사용량(별도 화면), 문의 티켓(별도 화면), 요금제 정의(별도 화면). 이 화면에서는 각 화면으로의 이동 링크만 제공한다.

## 2. 용어

| 용어 | 정의 |
|---|---|
| 업체 / 테넌트 | 서비스를 계약해 챗봇을 운영하는 고객사. 시스템상 격리 단위 |
| 원가율 | (해당 월 모델 원가 ÷ 해당 월 청구액) × 100 |
| 대리 로그인 | 운영자가 특정 업체의 담당자 권한으로 업체 대시보드에 진입하는 기능 |
| 쿼터 | 요금제에 포함된 월 대화 수·문서 수 한도 |
| 저장 답변 비율 | 전체 응답 중 공통 질문으로 처리되어 모델 원가가 발생하지 않은 비율 |

## 3. 화면 구조

```
운영 콘솔
└── 업체
    ├── 업체 목록          (기본 진입)
    │   ├── 필터 칩
    │   ├── 검색
    │   └── 목록 테이블
    └── 업체 상세          (목록에서 행 선택 시 우측 패널)
        ├── 요약
        ├── 사용량·원가
        ├── 조치
        ├── 내부 메모
        └── 활동 이력
```

목록과 상세는 **한 화면 좌우 분할**로 배치한다. 별도 페이지 이동 시 목록의 필터·스크롤 위치가 초기화되어, 여러 업체를 연속으로 확인하는 CS 업무 흐름이 끊기기 때문이다.

## 4. 화면 상세

### 4.1 업체 목록

#### 4.1.1 필터

칩 형태로 상시 노출하며, 각 칩에 해당 건수를 함께 표시한다. 건수가 0인 칩은 흐리게 처리하되 숨기지 않는다.

| 칩 | 조건 |
|---|---|
| 전체 | 해지 업체 제외 전체 |
| 체험 중 | `plan = trial` |
| 결제 실패 | 최근 결제 시도가 실패 상태 |
| 원가 초과 | 이번 달 원가율 ≥ 100% |
| 7일 미접속 | 담당자 최종 로그인이 7일 이전 |
| 일시정지 | `status = suspended` |
| 해지 | `status = churned` (기본 숨김) |

#### 4.1.2 검색

업체명, 도메인, 공개 키(`pk_live_...`), 담당자 이메일을 대상으로 부분 일치 검색한다. 문의 메일에 적힌 도메인만으로 찾을 수 있어야 하므로 도메인 검색은 서브도메인도 매칭한다.

#### 4.1.3 목록 컬럼

| 컬럼 | 내용 | 정렬 |
|---|---|---|
| 업체 | 업체명 + 도메인 | 가나다 |
| 요금제 | 요금제명 | — |
| 이번 달 대화 | 대화 수 | 가능 |
| 원가율 | 막대 + 백분율 | **기본 정렬(내림차순)** |
| 상태 | 상태 배지 | — |

기본 정렬을 원가율 내림차순으로 두는 이유는, 운영자가 매일 가장 먼저 확인해야 할 대상이 손실 계정이기 때문이다.

#### 4.1.4 원가율 막대

- 70% 지점에 기준선을 표시한다.
- 70% 미만 초록 / 70~99% 노랑 / 100% 이상 빨강.
- 100%를 넘어도 막대는 100%에서 멈추고, 숫자로만 초과분을 표기한다.

### 4.2 업체 상세

#### 4.2.1 요약

업체명, 상태 배지, 도메인, 공개 키를 상단에 고정 표시한다. 공개 키는 클릭 시 복사된다.

#### 4.2.2 항목

| 항목 | 비고 |
|---|---|
| 가입일 | |
| 요금제 · 월 청구액 | 다음 결제일 병기 |
| 이번 달 대화 | `사용 / 한도` 형식 |
| 학습 문서 수 | `사용 / 한도` 형식 |
| 공통 질문 수 | **0개면 강조 표시** — 원가 급증의 선행 지표 |
| 이번 달 모델 원가 | 원가율에 따라 색상 변화 |
| 마지막 접속 | 담당자 최종 로그인 |

#### 4.2.3 조치 버튼

| 버튼 | 동작 | 확인 절차 |
|---|---|---|
| 대리 로그인 | 해당 업체 대시보드 진입 | **사유 입력 필수** |
| 요금제 변경 | 요금제 선택 + 적용 시점 지정 | 확인 모달 |
| 쿼터 임시 증량 | 이번 달에 한해 한도 상향 | 증량분·사유 입력 |
| 체험 연장 | 체험 종료일 연기 | 연장 일수 선택 |
| 일시정지 | 챗봇 응답 중단 | 사유 입력 + 확인 모달 |

#### 4.2.4 내부 메모

자유 서술 텍스트. 저장 시 작성자와 시각이 함께 기록되며, 이전 메모는 이력으로 남는다. 영업 이력과 CS 대응 맥락이 담기므로 덮어쓰기가 아닌 누적 방식으로 설계한다.

#### 4.2.5 활동 이력

해당 업체에 대해 발생한 사건을 시간순으로 표시한다. 요금제 변경, 결제 성공·실패, 일시정지, 대리 로그인, 쿼터 조정, 문서 대량 업로드가 대상이다.

## 6. 대리 로그인 정책

이 기능은 남의 고객 데이터를 그대로 열람하는 행위이므로, 편의보다 통제를 우선한다.

### 6.1 실행 조건

1. 사유 입력 없이는 실행되지 않는다. 공백만 입력한 경우도 거부한다.
2. 진입 즉시 감사 기록에 적재된다. 이 기록은 삭제·수정할 수 없다.
3. 세션 유효 시간은 30분이며, 연장하려면 사유를 다시 입력한다.

### 6.2 세션 중 제약

| 허용 | 금지 |
|---|---|
| 모든 화면 조회 | 결제 수단 변경 |
| 설정 값 확인 | 팀원 초대·삭제 |
| 문제 재현을 위한 테스트 대화 | 계정 해지 |
| 지식 소스 상태 확인 | 문서 삭제 |

세션 중에는 화면 상단에 **"운영팀이 대리 접속 중"** 배너를 고정 노출한다. 운영자가 자기 계정으로 착각한 채 데이터를 변경하는 사고를 막기 위함이다.

### 6.3 업체 측 공개

업체 대시보드의 계정 화면에 운영팀 접속 이력(시각, 사유)을 노출한다. 숨기는 편이 편하지만, 공개하는 쪽이 신뢰 확보에 유리하며 개인정보 처리방침 고지 의무에도 부합한다.

## 7. 데이터 모델

```sql
-- 업체
CREATE TABLE tenants (
  id             uuid PRIMARY KEY,
  name           text NOT NULL,
  primary_domain text NOT NULL,
  publishable_key text UNIQUE NOT NULL,
  plan_id        uuid REFERENCES plans(id),
  status         text NOT NULL,   -- trial | active | suspended | churned
  trial_ends_at  timestamptz,
  created_at     timestamptz DEFAULT now()
);

-- 쿼터 조정 (임시 증량 이력)
CREATE TABLE quota_overrides (
  id          bigserial PRIMARY KEY,
  tenant_id   uuid NOT NULL REFERENCES tenants(id),
  period      date NOT NULL,         -- 적용 월
  conv_delta  int  DEFAULT 0,
  doc_delta   int  DEFAULT 0,
  reason      text NOT NULL,
  operator_id uuid NOT NULL,
  created_at  timestamptz DEFAULT now()
);

-- 내부 메모 (누적)
CREATE TABLE tenant_notes (
  id          bigserial PRIMARY KEY,
  tenant_id   uuid NOT NULL REFERENCES tenants(id),
  body        text NOT NULL,
  operator_id uuid NOT NULL,
  created_at  timestamptz DEFAULT now()
);

-- 감사 기록 (삭제 불가)
CREATE TABLE audit_logs (
  id          bigserial PRIMARY KEY,
  operator_id uuid NOT NULL,
  action      text NOT NULL,   -- impersonate | change_plan | grant_quota | suspend | view_conversations
  tenant_id   uuid,
  reason      text NOT NULL,
  meta        jsonb,
  created_at  timestamptz DEFAULT now()
);
CREATE INDEX ON audit_logs (tenant_id, created_at DESC);
```

### 7.1 목록 조회 성능

원가율은 매 요청마다 `ai_usage` 테이블을 집계하면 업체 수에 비례해 느려진다. **일 단위 집계 테이블**(`tenant_daily_usage`)을 별도로 두고, 목록에서는 이를 합산한다. 업체 상세에서만 실시간 집계를 허용한다.

## 9. 예외 처리

| 상황 | 처리 |
|---|---|
| 검색 결과 없음 | "조건에 맞는 업체가 없습니다" + 필터 해제 버튼 |
| 대리 로그인 중 대상 업체 해지 | 세션 즉시 종료 후 목록으로 이동 |
| 요금제 변경 중 결제 실패 | 변경을 롤백하고 기존 요금제 유지, 실패 사유 표시 |
| 쿼터 증량 후 월 마감 | 다음 달 자동 원복, 이력만 남김 |
| 삭제된 업체 상세 직접 접근 | "해지된 업체입니다" 안내 + 읽기 전용 표시 |
| 동시에 두 운영자가 같은 업체 수정 | 나중 저장이 반영되며, 충돌 시 경고 후 확인 |

## 11. 개발 단계

### 1단계 — 기본 (2주)
목록 조회·검색, 업체 상세, 상태 변경, 감사 기록 적재

### 2단계 — CS 대응 (2주)
대리 로그인, 쿼터 임시 증량, 내부 메모, 활동 이력

### 3단계 — 영업 (1~2주)
필터 칩, 체험 연장, 요금제 변경, CSV 내보내기

### 4단계 — 자동화 (이후)
조건 기반 알림, 일괄 조치, 이탈 예측 지표

---

## 12. 확인이 필요한 사항

1. 해지 업체의 데이터 보존 기간 — 벡터 데이터까지 즉시 삭제할지, 유예 기간을 둘지
2. 대리 로그인 이력을 업체에 공개하는 범위 — 사유 전문까지 보여줄지, 시각만 보여줄지
3. 원가율 경고 기준선 70% — 실제 서버비와 인건비를 반영해 재산정 필요
4. 몽골 법인 업체의 통화 표시 — 원화 환산 표시 여부
