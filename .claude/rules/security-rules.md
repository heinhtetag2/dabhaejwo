# Security Rules — 인증/인가/감사 원칙 (프레임워크 중립)

> 구체 구현(라이브러리, 어노테이션 등)은 각 스택 모듈이 정의. 여기는 모든 프로젝트가 지킬 원칙.

## 비밀 관리
- 시크릿·토큰·DB 비밀번호는 환경변수/외부 설정. 코드·설정 파일에 평문 커밋 금지. 로컬 설정 파일은 gitignore.
- 비밀번호 저장은 단방향 해시(BCrypt 등). 평문·복호화 가능 저장 금지.

## 인가
- **권한 검증의 진실은 서버다.** 클라이언트에서 버튼을 숨기는 것은 UX이지 보안이 아니다.
- 권한 체크는 선언적·일원화된 방식으로 (스택 모듈 참조). 핸들러마다 if-role 분기 흩뿌리기 금지.
- 권한 키 규약: `{RESOURCE}_{ACTION}` (예: `MEMBER_READ`). 권한 매트릭스는 `docs/intake.md`의 역할 매트릭스와 일치.
- 소유권 검증(본인 리소스만 수정)은 비즈니스 로직 레이어에서 명시적으로.

## 감사 로그 (처음부터, 빠짐없이)
- **관리자/운영자의 쓰기 액션(생성/수정/삭제/승인/거부)은 감사 로그 필수.** 새 도메인을 만들 때 같은 커밋에 포함한다. "나중에 추가"는 반드시 누락된다.
- 기록 항목: 행위자 id, 액션, 대상 리소스 타입+id, 변경 요약, 시각.
- 기록 경로는 하나로 일원화 (서비스/모듈 하나).

## 입력 검증
- 모든 외부 입력은 서버에서 검증. 클라이언트 검증은 UX용.
- 파일 업로드: 확장자·MIME·크기 화이트리스트 (stub 단계에서도 인터페이스에 검증 포함).
- 에러 응답에 스택트레이스·내부 구조 노출 금지.

## 관리자 영역
- 관리자 API/화면은 별도 경로 prefix + 강화된 접근 제어 (필요 시 IP 화이트리스트).
- 사용자/관리자 인증 체계가 분리되면 토큰/세션도 분리.
